The model

As a beat passes through the network, it gets shorter in time and richer in features. Each block below is drawn to scale: height is the number of time steps, width is the number of features.

Convolution: wave shapes Bidirectional LSTM: order in time Output: 5 class probabilities

Shape

Three Conv1D layers (64, 128 and 128 filters) learn local patterns such as the width and height of the QRS spike. Each is followed by batch normalisation and pooling.

Rhythm

A Bidirectional LSTM with 64 units in each direction reads those features forwards and backwards, so it sees what comes before and after every point in the beat.

Decision

Global average pooling, a 64-unit dense layer and dropout lead to a softmax over the five classes. The highest probability is the prediction.

Beat classes

MIT-BIH beat annotations are grouped into five classes following the AAMI standard. Each example on the right is a real beat from the test set.

How ECGense is delivered

Every change goes through the same automated path, from a commit on GitHub to new pods running in Kubernetes. Jenkins runs it; nobody copies files or restarts servers by hand.

  1. DeveloperChanges the code
  2. GitCommits the change
  3. GitHubStores the repository
  4. JenkinsNotices the new commit
  5. Testpytest with the real model
  6. Docker buildPackages the app
  7. KubernetesRolls out new pods on Kind
  8. ECGenseRunning and verified

Git and GitHub

All code, the trained model, the tests and the pipeline itself live in one Git repository on GitHub. The large MIT-BIH dataset stays out of Git; the tests use 20 real beats saved in samples/.

Jenkins

Checks GitHub every two minutes. When it finds a new commit it runs the five stages in the Jenkinsfile, stopping at the first one that fails, so a broken change never reaches the cluster.

  1. Checkout gets the latest code from GitHub
  2. Test runs 8 pytest tests against the real model
  3. Build Docker Image tags the image with the build number
  4. Deploy to Kubernetes loads the image into Kind and applies the YAML files
  5. Verify Deployment waits for the rollout and calls /health

Docker

Packages Python 3.12, TensorFlow, Flask and the trained model into one image, so it runs the same way on any machine. The app runs as a normal user, not root, behind the gunicorn web server.

Show the Dockerfile 
FROM python:3.12-slim
WORKDIR /app
COPY webapp/requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY webapp/ webapp/
COPY ecg_cnn_bilstm.keras .
COPY samples/ samples/
ARG BUILD_NUMBER=dev
ARG GIT_COMMIT=local
ENV BUILD_NUMBER=${BUILD_NUMBER} GIT_COMMIT=${GIT_COMMIT}
RUN useradd --create-home ecgense
USER ecgense
EXPOSE 5000
CMD ["gunicorn", "--bind", "0.0.0.0:5000", "--workers", "1",
     "--threads", "4", "--timeout", "120", "webapp.app:app"]

Kubernetes on Kind

Runs two copies (pods) of ECGense in their own ecgense namespace on a local Kind cluster. A pod only receives traffic after /health confirms the model has loaded, and Kubernetes restarts it if it stops responding.

Show the Deployment 
apiVersion: apps/v1
kind: Deployment
metadata:
  name: ecgense
  namespace: ecgense
spec:
  replicas: 2
  template:
    spec:
      containers:
        - name: ecgense
          image: ecgense:IMAGE_TAG   # Jenkins build number
          imagePullPolicy: IfNotPresent
          ports:
            - containerPort: 5000
          readinessProbe:
            httpGet: { path: /health, port: 5000 }
          livenessProbe:
            httpGet: { path: /health, port: 5000 }
